# 个人 AI OS · 产品需求清单

**日期：** 2026-10-12  
**状态：** 由播客总结压成；对照已实现规格做「已落地 / 待补 / 明确不做」  
**依据：** [`2026-10-12-shao-allen-justin-sun-podcast-summary.md`](./2026-10-12-shao-allen-justin-sun-podcast-summary.md)  
**实现规格：** [`2026-10-12-personal-ai-os-design.md`](./2026-10-12-personal-ai-os-design.md)

> 原则：抄「系统方法」，不抄「人生叙事 / 赛道押注 / 金句修辞」。产品是可调参的个人 OS，不是孙宇晨传记或投资顾问。

---

## 0. 产品一句话

用户登录后，在独立应用「个人 AI OS」里：沉淀可迁移的个人数据 → 用 AI 做带记忆的对话与日报 → 大事用多模型给出上中下策并由人拍板与回写反馈。

---

## 1. 从播客抽出的产品原则（必守）

| # | 原则 | 产品含义 |
|---|------|----------|
| P1 | 数据资产 > 模型忠诚 | 记忆/日志/决策可导出；模型可换，数据不绑死单一供应商 |
| P2 | 系统先跑起来 | 免费/低成本模型可用；设置里换模型，不强迫高价订阅 |
| P3 | AI 出草案，人拍板 | 任何建议都可拒绝/改选/反馈；禁止「自动执行人生决策」 |
| P4 | 先攒数据再重分析 | 日志与笔记可持续写入；决策可基于历史上下文，不鼓励空数据押赛道 |
| P5 | 反馈即调参 | 日报反馈、决策选择与事后评价要写回，影响后续生成语气/重点 |
| P6 | 开图优于内卷 | 决策模块强调多方案对比与样本式思考，而非单一「正确答案」 |
| P7 | 身体/日程是仪表盘入口 | 饮食/训练/睡眠/日程是日志类型，不是医疗诊断产品 |

## 2. 三块能力：该抄什么 / 不该抄什么

### 2.1 记忆（期 1）

**该抄**

- [x] 固定人设/档案（目标、约束、偏好）可编辑
- [x] 可检索笔记（生活/工作/决策碎片）
- [x] 对话组装时注入档案 + 相关笔记
- [x] 用户可调：记忆策略、人设、默认模型
- [x] 导出为 Markdown / 可迁移包（`GET /os/export`）

**不该抄**

- 要求用户「百分百听 AI」
- 把助手级高资源工作流当成默认 UX
- 一上来就做向量库/第二脑全家桶（当前 SQL LIKE 足够；向量检索明确非目标）

**验收要点**

- 改档案/笔记后，新对话能反映变化
- 关闭记忆相关模块时 API/UI 有明确禁用

---

### 2.2 日志 + 日报（期 2）

**该抄**

- [x] 日志类型：饮食 / 训练 / 睡眠 / 日程（健身入口 → 系统入口）
- [x] 按日生成 AI 日报（流式可选）
- [x] 对日报可反馈，用于后续调参
- [ ] 拍照估热量、训练视频纠姿、Oura 等可穿戴同步（播客示例；规格非目标 → **明确不做 v1**）
- [ ] 本地 MD 文件夹双向同步（理念对齐导出；实现可后置）

**不该抄**

- 医疗建议、处方式营养方案
- 强制每日热量缺口等个人指标写死进产品默认值
- 把「薄肌」叙事做成产品卖点文案

**验收要点**

- 有若干日志后可生成可读日报
- 反馈可查；模块关闭返回 403

---

### 2.3 多模型决策（期 3）

**该抄**

- [x] 同一问题并行多模型
- [x] 归一为上 / 中 / 下策展示
- [x] 用户选择 + 事后反馈可回写
- [x] 对比模型列表用户可配（设置 `model_prefs`）
- [x] 「先采样」式清单/模板（职业/项目/习惯开图模板）
- [x] 开图 checklist（资源/对手/版本/约束）作为决策提问脚手架

**不该抄**

- 自动替用户下注专业/行业/房车
- Crypto / 稳定币 / 全球商机等内容推荐做成默认模块
- Agent 微支付、算力套利等叙事进产品范围

**验收要点**

- 至少配置 2 个对比模型时可跑出三策
- 选择与反馈持久化可查

## 3. 功能需求清单（按优先级）

### Must（已对齐实现）

| ID | 需求 | 模块 | 状态 |
|----|------|------|------|
| M1 | 登录必填，独立路由 `/os` | Shell | 已落地 |
| M2 | 与 Prompt 工作台数据隔离；共用 JWT + ModelProvider | 平台 | 已落地 |
| M3 | Profile + Notes + Chat（含 SSE） | 记忆/对话 | 已落地 |
| M4 | 设置：人设、记忆策略、模块开关、模型偏好 | 设置 | 已落地 |
| M5 | Journal CRUD + Daily Report 生成/反馈 | 日志/日报 | 已落地 |
| M6 | Decision 线程、多模型 run、上中下、choose/feedback | 决策 | 已落地 |
| M7 | 模块关闭时对应能力 403 | 全站 | 已落地 |

### Should（产品化缺口，对照播客）

| ID | 需求 | 为什么要 | 建议优先级 |
|----|------|----------|------------|
| S1 | 一键导出：档案/笔记/日志/日报/决策 → Markdown ZIP | P1 可迁移数据资产 | **已落地** |
| S2 | 决策「开图」提问模板（约束、选项空间、已有样本、不可破底线） | P6 | **已落地** |
| S3 | 日报/决策反馈真正写入 profile 或策略字段（可观测的调参闭环） | P5 | **已落地** |
| S4 | 空数据引导：前 2–4 周以「攒日志」为主，弱推重大决策 | P4 | **已落地** |
| S5 | 低成本模型起步说明（设置页文案 + 默认推荐免费/按次） | P2 | **已落地** |

## 4. 非功能与边界

| 项 | 要求 |
|----|------|
| 安全 | 仅本人数据；JWT；无跨用户泄漏 |
| 合规文案 | 健康/投资相关 UI 标注「非医嘱/非投顾」 |
| 可观测 | 控制台无致命错误；流式失败有可理解回退 |
| 独立感 | 入口卡片「个人 AI OS」；不与 Trading / Prompt WB 混导航 |
| 诚实默认 | 默认关闭「自动采纳」类行为；选择权在用户 |

---

## 5. 用户故事速查（压成验收句）

1. **作为**用户，**我要**编辑人设与笔记，**以便**对话始终带着我的上下文。
2. **作为**用户，**我要**记录饮食/训练/睡眠/日程并生成日报，**以便**用数据而不是感觉复盘。
3. **作为**用户，**我要对**日报点赞/纠错，**以便**系统下次更贴合我。
4. **作为**用户，**我要把**同一难题丢给多个模型看上中下策，**以便**我来拍板而不是盲从。
5. **作为**用户，**我要**导出自己的数据，**以便**换模型/换工具时资产不丢。（Should / S1）
6. **作为**用户，**我要**关掉暂时不用的模块，**以便**界面与能力保持克制。

## 6. 与播客「可执行清单」的映射

| 播客动作 | 产品落点 |
|----------|----------|
| 建个人文件夹（MD） | Memory Notes + Journal；导出 S1 |
| 每日/每周 AI 报告 + 纠正 | Reports + feedback |
| 同题问 2–3 个模型 | Decisions + model_prefs |
| 大事先采样再下注 | 开图模板 S2（待补） |
| 便宜工具启动 | 设置换模型 + S5 |
| 身体当仪表盘 | Journal 类型字段 |
| 全球视角找机会 | **不进产品**（个人方法论，非功能） |

## 7. 结论：产品该长什么样

**做：** 可调参的个人记忆 OS + 生活日志日报闭环 + 多模型决策参谋（人拍板）。  
**不做：** 复制嘉宾人生观、赛道推荐引擎、医疗/投顾、可穿戴全家桶、模型锁定。  
**下一刀最值（已完成一轮）：** 数据导出（S1）→ 反馈真正调参（S3）→ 开图决策模板（S2）→ 空数据引导与低成本说明（S4/S5）。  
**仪表盘（已落地）：** `/os/dashboard` 汇总个人画像、模块计数、日志分布、钉选看板、个性化「如何优化个人 AI OS」指引；各模块可钉选条目。  
**仍后置：** 导出增强（聊天记录）、可穿戴/多模态、向量检索。
