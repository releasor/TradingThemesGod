# 题材详情研究信息与行情统计设计

## 背景与目标

当前题材详情页仅展示 `themes.description` 中的简短描述、题材级涨跌幅、热度、成分股数量、概念图谱和产业链数据，无法回答用户进入详情页后最关心的三个问题：题材具体是什么、近期由什么事件驱动、题材内部的涨跌分布如何。

本次改动为每个题材详情页增加：

- 由公开互联网资料生成的结构化详细介绍；
- 最近的题材驱动事件及可追溯原文来源；
- 最新交易日的涨停、跌停、上涨、下跌、平盘和停牌家数，以及上涨与下跌家数比。

所有研究结果持久化保存。详情页读取已落库数据，不在每次访问时实时抓取。系统通过定时增量任务维护数据，并提供当前题材的手动刷新入口。

## 范围

### 本次包含

- 新增题材详细介绍、题材驱动事件和题材市场快照的数据模型及迁移；
- 复用并完善现有公开网页搜索、正文抓取、反爬和 AI 模型能力；
- 增量采集、去重、AI 相关性判断、摘要生成和关键词降级；
- 从成分股行情及全市场涨跌停池计算题材市场快照；
- 扩展题材详情 API，并新增当前题材研究信息刷新接口；
- 在题材详情页展示详细介绍、来源、更新时间、最近驱动事件和行情统计；
- 后端、API 和前端相关测试。

### 本次不包含

- 保存或展示抓取网页的完整正文；
- 用户编辑题材介绍或人工标注驱动事件；
- 新建独立任务队列、消息中间件或外部云服务；
- 改变现有概念图谱、产业链和成分股功能的业务逻辑；
- 历史行情统计图表。本次仅持久化每日快照并展示最新有效快照，为未来趋势功能保留数据。

## 总体架构

功能拆分为三个相互独立的数据单元：题材档案、题材驱动事件和题材市场快照。三个单元分别由独立服务生成或聚合，由题材详情服务统一读取。任一单元更新失败时，不清空其他单元或该单元上次成功的数据。

现有 `themes.description` 继续承担列表页和卡片使用的简短描述，不写入长篇研究内容。结构化详细介绍存入单独表，避免列表查询载荷膨胀，也使研究结果可以独立刷新。

## 数据模型

### `theme_profiles`

每个题材最多一条详细档案：

- `id`：自增整数主键；
- `theme_id`：题材外键，唯一；
- `definition`：概念定义；
- `core_logic`：核心逻辑；
- `applications`：产业链或应用场景，JSON 数组；
- `catalysts`：主要催化因素，JSON 数组；
- `risks`：主要风险，JSON 数组；
- `sources`：资料来源列表，保存标题、URL、发布方和发布时间；
- `generated_at`：本次内容成功生成时间；
- `created_at`、`updated_at`：通用时间字段。

索引包括唯一索引 `idx_theme_profiles_theme_id`。删除题材时级联删除档案。

### `theme_driver_events`

保存经筛选后的题材驱动事件：

- `id`：自增整数主键；
- `theme_id`：题材外键；
- `title`：原始或规范化标题；
- `summary`：AI 生成的中文摘要；
- `source`：来源名称；
- `url`：原文地址；
- `url_hash`：标准化 URL 的 SHA-256；
- `published_at`：原文发布时间；
- `relevance_score`：题材相关性分数，范围 0 至 100；
- `crawled_at`：抓取时间；
- `created_at`、`updated_at`：通用时间字段。

使用题材与 URL 哈希的联合唯一索引防止重复，并为 `theme_id`、`published_at` 及二者组合建立查询索引。删除题材时级联删除事件。

### `theme_market_snapshots`

按题材和交易日期保存市场统计：

- `id`：自增整数主键；
- `theme_id`：题材外键；
- `trade_date`：交易日期；
- `up_count`：上涨家数；
- `down_count`：下跌家数；
- `flat_count`：平盘家数；
- `suspended_count`：停牌或无有效行情家数；
- `limit_up_count`：涨停家数；当日涨停池不可用时为 `null`；
- `limit_down_count`：跌停家数；当日跌停池不可用时为 `null`；
- `calculated_at`：统计计算时间；
- `created_at`、`updated_at`：通用时间字段。

题材和交易日期组成联合唯一索引。上涨与下跌家数比不单独存储，由 `up_count` 和 `down_count` 派生，避免数据不一致。删除题材时级联删除快照。

迁移文件使用 `alembic/versions/` 下的下一个连续序号，兼容项目当前 MySQL 8.0 和 SQLAlchemy 配置。

## 互联网采集与 AI 处理

### 详细介绍

详细介绍在以下情况更新：

- 题材尚无档案；
- 档案距上次成功生成已超过 7 天；
- 用户手动刷新当前题材资料。

搜索词由题材名称与“概念、产业链、应用、催化、风险”等限定词组合。系统通过现有公开网页研究服务搜索候选页面、校验公网 URL、提取正文，并把正文片段及来源元数据交给已配置的默认 AI 模型。模型必须输出符合固定结构的 JSON，只能基于输入来源生成内容，不得虚构来源。

当 AI 不可用或输出校验失败时，不用拼接网页文本覆盖已有档案。已有成功档案继续展示；首次生成失败时显示暂无详细介绍和友好的中文提示。

### 驱动事件

驱动事件默认每小时增量更新，同时支持手动刷新当前题材。候选数据来自现有财经新闻源和公开网页搜索。搜索关键词包含题材名称、题材别名、核心成分股名称，以及“政策、订单、发布、突破、涨价、扩产、业绩”等驱动语义。

处理顺序为：

1. 按标准化 URL 哈希过滤已处理记录；
2. 提取标题、正文摘要、来源和发布时间；
3. 使用 AI 判断事件与题材的相关性，合并同一事件的重复报道，生成中文摘要并给出相关性分数；
4. 只写入达到相关性阈值的事件，并保留代表性原文链接；
5. AI 不可用时，按题材名、成分股名和驱动关键词进行保守匹配，降级结果使用较低相关性分数并保留来源。

详情页先查询最近 7 天，按发布时间和相关性排序返回最多 5 条；不足 5 条时将时间范围扩展到 30 天，但仍最多返回 5 条。

### 反爬与降级

网页搜索和正文抓取统一复用项目的 UA 轮换、随机请求间隔、自动重试、代理支持和来源降级策略。候选来源按域名限速，单个来源失败不阻断整批任务。所有 URL 在请求前和重定向后都执行公网地址校验，禁止访问本机、内网、凭证型 URL 和非 HTTP/HTTPS 地址。

数据库仅保存生成后的摘要及必要来源元数据，不保存完整网页正文。前端提供原文链接，用户可返回来源站点查看完整内容。

## 行情统计

### 涨跌家数

题材成分股以最新有效涨跌幅分类：

- 大于 0：上涨；
- 小于 0：下跌；
- 等于 0：平盘；
- 缺少有效价格或涨跌幅：停牌或无有效行情。

上涨与下跌家数比使用 `up_count:down_count` 展示，同时显示数值比率。`down_count` 为零时不执行除法，数值比率显示为“—”，但仍显示家数形式，例如 `12:0`。平盘和停牌不进入比率分母。

### 涨跌停家数

涨停和跌停不根据固定百分比阈值推断。行情任务抓取当日全市场涨停池与跌停池，标准化股票代码后，与题材成分股集合取交集。该方式覆盖主板、创业板、科创板、北交所、ST 股票及特殊交易状态下不同的价格限制。

行情统计随现有成分股行情任务更新。交易时段可重复覆盖当日同一快照，收盘后保存最终结果。只有成功获得对应交易日的涨停池或跌停池时，才把相应字段写为整数；抓取失败时保留当日已有成功值，若当日从未成功则写为 `null`。这样可以明确区分真实的零家和数据不可用。

## API 设计

### 题材详情

`GET /api/v1/themes/{theme_id}` 保留现有字段，并增加：

- `profile`：结构化详细介绍、来源及生成时间，无数据时为 `null`；
- `recent_driver_events`：驱动事件列表，可能为空数组；
- `market_snapshot`：最新有效市场快照，无数据时为 `null`。

上涨与下跌数值比可在响应层派生为 `up_down_ratio`，当下跌家数为零或没有有效上涨/下跌样本时为 `null`。响应还应包含明确的交易日期或更新时间，避免用户把旧数据误认为实时数据。

### 手动刷新

新增 `POST /api/v1/themes/{theme_id}/insights/refresh`，刷新当前题材的详细介绍和驱动事件。该接口不重复触发全市场行情及涨跌停池采集。响应包含：

- 题材 ID 和名称；
- 档案是否更新；
- 候选事件数、新增数、更新数和忽略数；
- 成功及失败来源；
- 刷新完成时间；
- 中文结果消息。

允许部分成功。题材不存在返回 404；所有来源均失败且没有可保留旧数据时返回项目统一格式的友好错误。AI 不可用但关键词降级成功时视为成功，并在响应中注明使用降级策略。

## 前端设计

### 顶部摘要区

保留题材名称、分类、热度、题材涨跌幅和成分股数量。新增紧凑的市场广度区域，展示：

- 涨停家数；
- 跌停家数；
- 上涨家数；
- 下跌家数；
- 上涨:下跌家数及数值比率；
- 数据对应交易日期。

涨跌颜色遵循项目现有主题色约定。没有有效快照时显示“暂无行情统计”，不显示一组可能引起误解的零。

### 题材详细介绍

位于顶部摘要区下方、图表和图谱之前，按以下结构展示：

- 概念定义；
- 核心逻辑；
- 产业链或应用场景；
- 主要催化因素；
- 风险。

底部显示资料更新时间和来源链接。没有档案时提供明确空状态，并引导用户使用“刷新题材资料”。

### 最近驱动事件

详细介绍后展示最多 5 条时间线事件。每项包含日期、标题、中文摘要、来源、相关性标识和原文链接。事件不足时不填充虚假占位内容；无事件时显示“近 30 天暂未发现可靠驱动事件”。

### 刷新与既有内容

新增“刷新题材资料”按钮，与现有“刷新图谱”按钮保持独立。刷新时按钮显示进行中状态，成功后使题材详情查询失效并重新获取；失败时保留当前页面数据并展示中文错误提示。

原有热度趋势、概念图谱、成分股和产业链区域继续保留在驱动事件之后。桌面端采用易扫描的分栏或网格，移动端按介绍、行情统计、事件顺序单列排列，文本和链接不得横向溢出。

## 错误处理与数据一致性

- 每个来源独立捕获超时、连接、解析和状态码异常；
- 单一来源失败不终止其他来源；
- 新结果只有在结构校验和数据库事务成功后才替换旧档案；
- 事件使用增量写入和唯一约束实现幂等；
- 快照的成分股集合和涨跌停池必须属于同一交易日期；
- 部分数据不可用时返回已有模块，不因一个嵌套字段失败而令整个题材详情接口失败；
- 前端展示最后成功更新时间，并区分“零”和“不可用”；
- 日志记录题材 ID、来源、阶段、耗时、候选数、写入数和失败原因，不记录模型密钥或完整网页正文。

## 测试策略

### 后端

- Alembic 升级可创建三张表、索引、唯一约束和外键；
- 题材档案一对一写入、成功替换和失败保留旧数据；
- 驱动事件 URL 标准化、增量去重、相关性阈值、重复报道合并和 AI 降级；
- 最近事件先取 7 天、不足时扩展到 30 天且总数不超过 5；
- 涨、跌、平盘、停牌分类准确；
- 涨跌停池与题材成分股交集准确；
- 下跌家数为零时比率为 `null`，但家数形式保留；
- 详情 API 在完整数据、部分缺失、全部缺失和题材不存在时响应正确；
- 刷新接口在全部成功、部分成功、AI 降级和来源全部失败时返回统一中文响应；
- URL 公网校验、重定向校验和来源超时不被绕过。

所有测试使用契约驱动的模拟 HTTP 响应和模型适配器，不访问真实互联网。

### 前端

- 顶部正确展示六类市场统计、交易日期和上涨:下跌比；
- `0` 与不可用状态区分正确；
- 结构化介绍、资料来源和更新时间正确渲染；
- 事件时间线最多展示 5 条，原文链接安全打开；
- 档案、事件和行情分别覆盖加载、空数据、旧数据保留及错误状态；
- 手动刷新成功后重新获取详情，失败时不清空页面；
- 桌面和移动布局不溢出，现有详情页功能保持可用。

## 验收标准

- 每个有研究数据的题材详情页均显示结构化详细介绍、来源和更新时间；
- 详情页显示近 7 天最多 5 条可靠驱动事件，不足时自动扩展至 30 天；
- 每条事件都能追溯到原文，并包含发布时间、来源和中文摘要；
- 详情页显示最新有效交易日的涨停、跌停、上涨、下跌家数及上涨:下跌比；
- 平盘、停牌和数据不可用状态不会被错误计入涨跌比；
- 定时任务增量更新且不会重复写入相同事件；
- 手动刷新只更新当前题材研究信息，成功或失败均有友好的中文反馈；
- 任一外部来源或 AI 服务失败不会清空上次成功数据，也不会阻断详情页其他模块；
- 新增后端和前端测试通过，现有相关测试无回归。
