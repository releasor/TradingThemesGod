# 市场表现板块拆分设计

## 背景

当前系统把东方财富提供的所有板块都作为题材处理，导致“昨日涨停”“昨日连板”“最近多板”等市场行为板块进入题材总数、排行、搜索、分类和导出。这些板块描述的是股票近期表现或交易行为，不属于实际题材。

本次改动将市场行为板块统一归入“市场表现”，从实际题材数据集中排除，并在仪表盘中使用独立区域展示。数据更新完成后，实际题材和市场表现数据同时刷新，更新成功或失败继续通过明确提示反馈。

## 分类范围

后端维护集中、显式的东方财富板块代码集合，以板块代码为唯一分类依据，不使用名称关键词进行运行时判断。

首批市场表现范围包括：

- 打板、首板、二板及以上表现
- 连板及含一字连板
- 昨日涨停及含一字涨停
- 昨日炸板、昨日触板
- 最近多板
- 题材股、趋势股、反转股
- 东方财富热股
- 昨日高换手
- 近期新高、百日新高、历史新高等同类现有行情板块

分类集合使用现有数据中已核实的板块代码初始化。后续发现新的同类板块时，仅扩充该集中集合。名称仅用于展示，因此真实题材即使名称含有“涨停”或“新高”等文字也不会被误分类。

## 后端设计

### 分类模块

新增独立分类模块，提供：

- 市场表现板块代码常量集合
- 判断给定板块代码是否属于市场表现的纯函数
- 可复用的 SQLAlchemy 查询条件

分类逻辑不写入数据库，不新增迁移，也不改变现有抓取数据结构。

### 实际题材查询

以下现有查询统一排除市场表现板块：

- 题材分页列表及搜索
- 热度排行和涨跌排行
- 题材分类列表
- 题材导出流

排除条件同时用于数据查询和总数统计，保证分页总数、题材总数及列表内容一致。题材详情接口保留按代码访问能力，使用户可从市场表现区域进入现有详情页。

### 市场表现接口

新增 `GET /api/v1/themes/market-signals`，返回市场表现板块列表。接口复用现有题材摘要数据结构，默认按热度或现有稳定排序输出，并允许前端取得当前全部已识别记录。

该静态路由必须声明在 `/{theme_code}` 动态详情路由之前，防止 `market-signals` 被识别为题材代码。

接口错误沿用项目统一错误响应和中文用户提示，不引入新的错误格式。

## 前端设计

### 数据访问

在题材 API 模块增加市场表现请求函数，并由 TanStack Query 使用独立查询键加载。更新任务成功后，同时使实际题材排行、涨跌排行和市场表现查询失效并重新获取。

### 仪表盘布局

在现有实际题材内容下方增加独立的“市场表现”区域：

- 使用不嵌套卡片的紧凑响应式网格
- 每项展示板块名称、涨跌幅和股票数
- 涨跌颜色遵循当前项目约定
- 点击项目进入现有题材详情页
- 桌面端适合快速扫描，移动端自动减少列数且文字不溢出

该区域不参与“题材总数”统计。题材总数应取实际题材列表接口返回的真实总数，不再使用当前排行数组长度。

### 状态处理

- 加载中：显示尺寸稳定的骨架占位
- 空数据：显示“暂无市场表现数据”
- 请求失败：区域内显示友好的中文错误，不阻断实际题材内容
- 更新成功：两类查询刷新后保留现有成功反馈
- 更新失败：保留失败原因反馈，页面继续显示上一次成功加载的数据

## 数据流

1. 爬虫继续按现有结构增量写入所有板块。
2. 实际题材接口在仓储查询层排除市场表现代码。
3. 市场表现接口仅查询这些代码。
4. 仪表盘并行加载实际题材排行、涨跌排行、实际题材总数和市场表现。
5. 手动或自动更新成功后，相关查询统一重新获取；失败时不清空已有数据。

## 测试策略

后端测试覆盖：

- 分类纯函数正确识别已知代码和普通题材代码
- 实际题材分页查询的数据和总数都包含排除条件
- 排行、分类和导出查询应用相同排除条件
- 市场表现仓储查询只包含指定代码
- 新接口返回正确响应，并验证静态路由不被详情路由拦截

前端测试覆盖：

- API 请求使用正确路径
- 仪表盘将市场表现渲染在独立区域
- 市场表现不计入题材总数
- 空数据和失败状态显示中文反馈
- 更新成功后触发市场表现查询刷新
- 市场表现项目可进入详情页

实现遵循测试先行：先增加会因缺少分类或接口而失败的测试，确认失败原因正确后，再增加最小实现使其通过。

## 非目标

- 本次不增加数据库 `theme_type` 字段或 Alembic 迁移
- 不改变爬虫抓取范围和增量更新策略
- 不重构题材详情页
- 不允许用户在前端自行编辑分类规则
- 不通过模糊名称关键词自动推断未知板块

## 验收标准

- 市场表现板块不再出现在实际题材列表、排行、分类、导出和题材总数中
- 所有已识别市场表现板块在仪表盘独立区域展示
- 独立区域支持加载、空数据、失败和点击详情状态
- 更新结束后明确反馈成功或失败；成功时两个区域都刷新
- 后端与前端相关新增测试通过，且不引入新的针对性测试回归
