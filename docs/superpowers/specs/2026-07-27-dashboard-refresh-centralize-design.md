# 看板刷新集中化与多源竞速设计

日期：2026-07-27  
状态：已实现（2026-07-27）（实现计划见 `docs/superpowers/plans/2026-07-27-dashboard-refresh-centralize.md`）  
方案：A（前端分板块编排 + 后端先拉后落库竞速）

## 目标

1. 顶部只保留 **轻量刷新** 与 **全量更新**；刷新除实时资讯外的全部看板内容。
2. 短线机会雷达、一进二打板参考等板块内刷新入口取消，统一由顶部触发。
3. 刷新可随时在前端 **取消**；已成功板块保留数据与刷新时间；未完成板块不覆盖旧数据。
4. 各细粒度板块单独展示刷新时间。
5. 全量更新展示进度条。
6. **轻量与全量**均支持多源并行竞速：并行拉数，**仅胜出源写入正式库**。

## 决策摘要

| 项 | 选择 |
|---|---|
| 架构 | 方案 A |
| 轻量 vs 全量 | 轻量=快数据竞速+分板块刷新；全量=全量采集竞速落库后再分板块刷新 |
| 多源落库 | 并行拉到草稿，仅胜出 commit（选项 3） |
| 竞速范围 | 轻量与全量都要 |
| 自动刷新 | 移除 |
| 分栏时间 | 细粒度（热度榜、涨幅榜、策略卡、短线雷达、一进二等） |
| 实时资讯 | 完全隔离，不参与顶部刷新 |

与既有文档关系：`2026-07-27-refresh-quotes-decouple-design.md`（全量不挡轻量）仍然有效；本设计在其之上增加集中化、可取消、分板块原子更新与多源竞速落库。

---

## §1 顶部控件与范围

### 保留

- **轻量刷新**：多源竞速更新快数据后，按板块刷新看板（不含资讯）。
- **全量更新**：多源竞速全量采集，仅胜出源落正式库；进度条；完成后同样分板块刷新。
- **取消**：进行中显示；可随时点；已成功板块保留，未完成不覆盖。

### 移除

- 自动刷新开关与间隔选择。
- 短线雷达「刷新信号」、一进二「实时刷新」。
- 全量「单选数据源」下拉（改为固定多源并行竞速）。

### 不碰

- `NewsTimeline` 自带刷新、自动刷新、频道过滤。

### 忙碌态

- 同一时刻用户只发起一种刷新（轻量与全量 UI 互斥）；进行中显示状态与「取消」。
- 若后台已有全量采集在跑，仍允许再点轻量（延续解耦锁：全量不挡轻量）。

---

## §2 分板块原子更新与时间戳

### 板块

| 板块 | 数据边界 | 成功条件 |
|---|---|---|
| 题材热度榜 | `theme-ranking` | 完整响应后才写入缓存 |
| 题材涨幅榜 | `theme-rise-ranking` | 同上 |
| 市场策略卡 | strategy overview / refresh-data | live 刷新 + overview 完整成功 |
| 短线机会雷达 | short-term signals / sectors | refresh + sectors 完整成功 |
| 一进二打板参考 | first-to-second | refresh POST + GET 完整成功 |
| 市场/指标信号 | `market-signals` / `indicator-signals` | 对应 GET 完整成功 |

QuickStats 等汇总数字随相关板块成功而更新；失败则不改对应数字。

### 原子规则

1. 板块请求完整成功 → 才 `setQueryData` / 替换该 query → 才更新「刷新于 HH:mm:ss」。
2. 取消 / 失败 / 超时 / 半截响应 → 不覆盖缓存，保留旧数据与旧时间。
3. 去掉误导性「全局单一上次更新」为主展示；以各板块分栏时间为准（可选：顶栏显示「最近一次成功板块时间」作辅助）。

### 取消

- 前端 `AbortController` 中止进行中的 HTTP。
- 后端已 commit 的胜出写入无法由前端撤销；前端仍只更新已成功拉取的板块 UI。

### UI

- 各板块标题旁：`刷新于 10:32:15`（无记录则「暂无」）。
- 刷新中该板块可显示「刷新中…」，不影响已完成板块。

## §3 轻量 / 全量流水线与多源竞速落库

### 共同原则

- **并行拉数，单路落库**：多源同时跑；先产出完整可用结果者胜出；仅胜出写入正式表；落败 cancel 并丢弃草稿。
- 取消：若胜出尚未 commit，正式库不变；若已 commit，以库为准，前端仍按 §2 只更新已拉成功的板块。

### 轻量流水线

1. **题材行情竞速**（改造 `POST /scraper/refresh-quotes`）  
   并行可用轻量源（至少 eastmoney；具备能力的 akshare 等一并纳入）→ 草稿完整结果 → 胜出再写正式题材涨跌/热度。
2. **策略卡 live**（`POST /short-term/overview/refresh-data`）：内部竞速或复用 quote race。
3. **短线信号** `POST /short-term/signals/refresh`（鉴权保持现状）。
4. **一进二** `POST /short-term/first-to-second/refresh`。
5. **读侧分板块**：热度榜 / 涨幅榜 / 市场信号 / 指标信号 / 策略 overview / sectors / 一进二 GET — 每块独立、可取消、成功才更新 UI+时间。

行情写入成功后再拉依赖涨跌的榜单，避免读到旧数。2–5 在写依赖满足后可部分并行。

### 全量流水线

1. **全量竞速**（替换串行 `runScraperWithFallback`）  
   - 并行启动 `dashboard_selectable` 源（如 eastmoney、akshare 等）。  
   - 各源爬到草稿（不写或写隔离区）→ 先完整完成者胜出 → 一次性 commit 进正式题材/成分股。  
   - 落败：cancel + 丢弃草稿。
2. 进度见 §4。
3. 落库成功后跑与轻量相同的分板块读/补刷，同样可取消、按块提交。

### 后端契约（要点）

| API | 作用 |
|---|---|
| `POST /scraper/run-race`（或等价扩展） | 启动全量多源竞速，返回 `race_id` |
| `GET /scraper/race/{id}` | 进度（各源 %、阶段、胜出源） |
| `POST /scraper/race/{id}/cancel` | 取消竞速 |
| `POST /scraper/refresh-quotes` | 内部多源竞速 + 单路落库；支持取消（可与 race cancel 模型对齐） |

单源 `POST /scraper/run/{source}` 可保留给运维；看板不再使用串行 fallback。

### 失败

- 全部源失败 → 该步骤失败；已成功的后续板块仍保留。
- 单源失败不影响其他源继续竞速。

## §4 全量进度条与实时资讯隔离

### 进度条

- 全量进行中：顶部刷新区下方进度条 + 阶段文案。
- 阶段示例：`多源竞速中` → `已选定 {source}` → `落库中` → `刷新热度榜…` 等。
- 进度值：竞速取各源进度 **max**；落库占固定区间（如 70%→90%）；分板块按完成数线性到 100%。
- 轻量：简短状态文案即可，不强制粗进度条。
- 取消后收起进度条，提示「已取消，已保留成功板块」。

### 资讯隔离

- 轻量 / 全量 / 取消永不调用 `POST /news/refresh`，不 invalidate `['news']`。
- 资讯刷新时间与看板分板块时间互不影响。

---

## 非目标

- 不改造实时资讯产品逻辑。
- 不在本期做 SSE/WebSocket 总任务总线（方案 B）。
- 不允许多源同时写入正式表再靠「后写覆盖」（方案 C）。
- 不恢复自动刷新（明确移除）。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 多源并行打源站触发限流 | 限制参与竞速的源集合；失败源快速退出；保留 rate limit |
| 全量草稿/隔离实现成本高 | 优先「内存/临时结构 hold 结果，胜出再走现有 save 路径」；避免双写正式表 |
| 取消时后端已 commit | 接受库已新、UI 按块拉取；文档与 toast 说明 |
| 竞速「完整」定义模糊 | 每源定义明确完成条件（条目数阈值、无致命错误）后再宣称可胜出 |

## 验收清单

- [x] 顶部仅轻量 + 全量 +（进行中）取消；无自动刷新、无源下拉
- [x] 短线雷达 / 一进二无独立刷新按钮
- [x] 轻量与全量均刷新除资讯外内容；资讯不受影响
- [x] 取消后已成功板块数据与时间保留，未完成不覆盖
- [x] 热度榜、涨幅榜、策略卡、短线雷达、一进二、信号区各自显示刷新时间
- [x] 全量有可见进度条与阶段文案
- [x] 轻量/全量多源并行；仅胜出源写入正式库
- [x] 全量进行中轻量仍可用（延续解耦锁设计）

### 实现备注（全量竞速兜底）

全量多源竞速中，若某源草稿仅有题材、无成分股（如 akshare themes-only），只作为兜底胜出：优先选用「题材 + 成分股」均完整的草稿；仅当无完整源可用时才 commit themes-only 结果。
