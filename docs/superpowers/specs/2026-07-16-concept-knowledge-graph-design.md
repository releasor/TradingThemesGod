# 概念题材深度知识图谱设计

## 目标

将题材详情从固定的上游、中游、下游三段展示，升级为可无限下钻的概念知识树。每个细分节点记录技术定义、产业链位置、核心逻辑、催化因素、风险、可信来源，并与真实成分股建立带理由的多对多关联。

机器人题材作为第一份完整样板，至少覆盖本体、核心零部件、灵巧手、关节、感知、控制、动力、材料、系统集成和应用场景。其中灵巧手继续拆分驱动、传动、传感，传感继续拆分电子皮肤，并关联福莱新材等具备明确业务逻辑的股票。

## 数据结构

新增 `concept_nodes` 表，以 `parent_id` 自关联形成任意深度树。节点包含：

- `name`、`node_type`、`description`
- `chain_level`：可选的上游、中游、下游标签，仅作为分析维度
- `market_logic`：该细分与题材及资本市场的关联逻辑
- `catalysts`、`risks`：结构化列表
- `sources`：来源名称、URL、发布日期组成的 JSON 列表
- `confidence`：0 到 1 的可信度
- `depth`、`sort_order`：稳定展示顺序

新增 `concept_node_stocks` 表连接节点和股票，保存 `relation_type`、`rationale`、`relevance_score`、`is_core` 和独立来源。股票只能从数据库现有股票中按代码关联，不创建虚构证券。

## API 与兼容

`GET /api/v1/themes/{id}` 增加 `concept_graph` 字段，返回统计信息和递归根节点。每个节点携带直接关联股票及子节点。旧 `industry_chains` 和 `chain_stock_counts` 暂时保留，避免破坏已有调用；由本地均分产生的记录清除后返回空数据。

服务层一次查询节点、关联和股票，在内存中按 `parent_id` 构树，避免递归 N+1 查询。无图谱的题材返回空根节点和零统计，不生成猜测数据。

## 前端交互

题材详情新增“概念深度图谱”工作区，默认展开前两层。节点可逐层展开，显示技术说明、市场逻辑、产业链标签、可信度、催化因素、风险和关联股票理由。顶部提供全部展开、全部收起和关键词过滤；移动端保持单列树形阅读。

上中下游饼图仅在存在真实分类时展示。原三列产业链组件移到次要位置；没有可信数据时不显示三等分结果。

## 数据治理

机器人知识树由版本化种子文件维护，按题材名称和股票代码幂等导入。每条股票关联必须有具体理由，来源不足时降低可信度或不建立关联。后续题材使用同一结构逐个增加知识包，不允许按股票数量、名称顺序或随机方式自动分类。

应用启动不再执行 `local_chain`。导入脚本清除描述中带“基于现有成分股结构推导”的本地伪数据，并将对应 `theme_stocks.chain_level` 置空，不删除外部可信来源记录。

## 验证

- 后端单元测试覆盖递归构树、空图谱、股票关联理由和幂等导入。
- API 测试覆盖机器人至少四层路径和福莱新材关联。
- 前端测试覆盖递归展开、过滤、股票理由以及空状态。
- 执行迁移和机器人导入后，通过浏览器验证桌面与移动端无重叠、可下钻且接口数据一致。
